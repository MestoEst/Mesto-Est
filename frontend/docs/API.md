# API «Место есть»: как фронтенд ждёт данные от бэкенда

Этот файл для Насти и для всех, кто пишет сервер. Код фронтенда по разделам: `static/js/api/` (зоны, аренда, владелец места) и `static/js/auth/auth.js` (аккаунт; короткая памятка в `docs/AUTH.md`). Фронтенд уже умеет обращаться ко всем адресам ниже и проверен на пробном сервере, который реализует именно этот контракт. Описание дополнительных разделов ниже — контракт для дальнейшего подключения. Парковочные места уже используют обязательный API, без демо-подмены; подробности в ../../docs/spot-ids/README.md.

## Как включать разделы
В `templates/mesto_prototype.html` есть строка:

```html
<script>window.MESTO_CONFIG = {api: {zones: false, marks: false, spots: true, auth: false, owner: false, listings: false, bookings: false}};</script>
```

Раздел готов на сервере, меняем его `false` на `true`. Больше ничего в JavaScript трогать не нужно.

| Флаг | Что включает |
|---|---|
| `zones` | прогноз «обычно свободно» берётся с сервера вместо демо-профиля |
| `marks` | будущий API зонных отметок; текущий флаг false |
| `auth` | регистрация, вход, выход, паспорт, восстановление сессии после перезагрузки |
| `owner` | статус владельца места и документы |
| `listings` | объявления «Сдать место» и список «Аренда» |
| `bookings` | брони, подтверждение владельцем |

## Общие правила
- Формат: JSON (кроме загрузки файлов, там `multipart/form-data`). Кодировка UTF-8.
- Авторизация: обычная сессия Django (cookie `sessionid`). Токены не нужны.
- CSRF: фронтенд читает cookie `csrftoken` и шлёт заголовок `X-CSRFToken` во всех не-GET запросах. Чтобы cookie появилась, страница приложения должна отдаваться через `@ensure_csrf_cookie` (см. `backend-draft/main/api_zones.py`).
- Ошибки: нужный HTTP-код и тело `{"error": "Текст, который увидит человек"}`. Фронтенд показывает этот текст как есть, поэтому по-русски и без технических слов. Коды: 400 неверные данные, 401 нужен вход, 403 нельзя, 404 нет такого, 409 уже есть, 413 файл большой, 415 не тот тип файла, 429 слишком часто.
- Сервер считает цены, итоги и права сам и не доверяет тому, что пришло с фронтенда.

## Парковочные места: действующий контракт

Карта получает `GET /api/spots/`: GeoJSON `{type:"FeatureCollection", dataset:"canonical-v1", zones:[...], features:[...]}`. Каждая зона имеет `id`, `display_number`, `display_order`, `name`, `street_id`, `street_name`. Feature содержит физический Polygon и properties: `id`, `zone`, `display_number`, `display_order`, `row_id`, `is_occupied`, `updated_at`, `usual_free_percent`. Совместимые псевдонимы: `code=id`, `block=zone`.

`id` не зависит от зоны, координат и порядкового номера. `is_occupied=null` — неизвестно, а не свободно. SPOTS.counts отдельно учитывает неизвестные места; прежний оценочный вид main (freeEst, зелёные/чёрные места и машинки) восстановлен отдельно от подтверждённых статусов. Поле appearance хранит только параметры этого оформления и не является отметкой занятости. `POST /api/spots/<id>/status/` принимает `{"is_occupied":true}` или false и сохраняет статус/историю/статистику только этого канонического места. `GET /api/spots/<id>/heatmap/` возвращает статистику места. Флаг `spots:true` оставлен в конфигурации для ясности; сама загрузка и запись мест обязательны и не подменяются демо при его выключении.

Ошибки загрузки показываются с повторной загрузкой. Источник первоначального импорта — `main/data/spots.geojson`. Переход со старых данных выполняется отдельно, без переноса истории; см. ../../docs/spot-ids/README.md.

## Зоны и отметки (отдельный, пока не реализованный API)

Флаги `zones` и `marks` остаются false. Приведённые ниже endpoints зон — прежний проект контракта, их нет в актуальном Django. Зонная отметка не вызывает POST для отдельного места и не меняет его статус. При выборе места отправляется его постоянный ID в действующий API выше. Прежнее сопоставление через zones.json отменено.

**GET `/api/zones/`**, ответ:
```json
[{"id": "z44", "name": "Зона 44", "spots": 30,
  "usual": {"wd": [null, 82, 80, "…24 числа…"], "we": ["…24 числа…"]}}]
```
`usual` это процент отметок «свободно» по часам (0–23) для будних (`wd`) и выходных (`we`). `null`, если за час меньше 5 отметок: для оценочного прогноза используется прежний профиль main, отдельно от подтверждённых текущих статусов.

**GET `/api/marks/?minutes=180`**: свежие отметки всех жителей.
```json
[{"id": 7, "zone": "z44", "kind": "free", "at": "2026-10-23T13:05:11+03:00"}]
```

**POST `/api/zones/<код>/marks/`**, тело `{"kind": "free" | "busy", "lat": 53.95, "lng": 27.66, "accuracy": 12}`, ответ 201 с одной отметкой (как выше). Гость тоже может отмечать. Повторная отметка той же зоны с той же сессии за 15 секунд: 429.

**DELETE `/api/zones/<код>/marks/<id>/`**: отменить свою отметку (кнопка «Отменить»), ответ 204.

## Аккаунт (флаг `auth`)
Код: `static/js/auth/auth.js`, памятка по подключению: `docs/AUTH.md`.
**POST `/api/auth/register/`**, тело:
```json
{"surname": "Иванова", "name": "Анна", "patronymic": "", "phone": "+375291112233", "email": "a@mail.by", "password": "secret1"}
```
Ответ 201: пользователь (формат ниже), сессия уже открыта. Почта занята: 409 «Такая почта уже зарегистрирована». Пароль от 6 знаков.

**POST `/api/auth/login/`** `{"email", "password"}`: ответ 200 пользователь, неверно 401. **POST `/api/auth/logout/`**: 204. **GET `/api/me/`**: пользователь или 401 (фронтенд спрашивает при загрузке страницы).

**PUT `/api/me/passport/`** `{"pid": "3010190A001PB1", "passport": "MP1234567"}`: проверить формат (ИН 14 символов, паспорт 2 буквы и 7 цифр), хранить зашифрованно. Ответ `{"passport_set": true, "pid_masked": "301•••••••••B1", "passport_masked": "MP•••67"}`.

Формат пользователя:
```json
{"id": 101, "surname": "Иванова", "name": "Анна", "patronymic": "", "phone": "+375…", "email": "a@mail.by",
 "passport_set": true, "pid_masked": "301•••••••••B1", "passport_masked": "MP•••67",
 "owner": { …см. следующий раздел… }}
```
Полный ИН и паспорт наружу не отдаём никогда.

## Владелец места (флаг `owner`)
Код: `static/js/api/owner.js` (запросы) и `static/js/features/owner/owner.js` (интерфейс).
Состояние владельца:
```json
{"is_owner": true, "status": "pending", "parking": "s2", "addr": "", "place": "128",
 "reject_reason": "", "submitted_at": "23.10 13:20",
 "documents": [{"id": 5, "kind": "title", "name": "dogovor.pdf", "size": 14231}]}
```
`status`: `none` (не владелец), `draft` (указано, документов не хватает), `pending` (на проверке), `verified`, `rejected`. `parking`: id улицы (`s1`…`s5`: ул. Пилотная, Небесная, Авиационная, Леонардо да Винчи, Михаила Миля; список приходит в метаданных зон из `/api/spots/`) или `other` (тогда заполнен `addr`). `kind` документа: `title` (документ на место: свидетельство о госрегистрации, договор или выписка), `tp` (технический паспорт), `other`.

- **GET / PUT `/api/me/owner/`** `{"is_owner", "parking", "addr", "place"}`: сохранить поля. Выключили галочку: статус `none`.
- **POST `/api/me/owner/documents/`** (`multipart`: `kind`, `file`): до 10 МБ, pdf/jpg/png/heic/webp, проверять тип по содержимому, а не только по имени. Ответ 201 `{"id", "kind", "name", "size"}`. Документ `title` и `tp` заменяет предыдущий. После загрузки статус из `pending/verified/rejected` возвращается в `draft`.
- **DELETE `/api/me/owner/documents/<id>/`**: 204.
- **POST `/api/me/owner/submit/`**: нужны `place`, документ `title` и `tp`, иначе 400. Ставит `pending`, возвращает состояние владельца.
- Проверку делает человек в админке (на следующей неделе): `verified` или `rejected` с `reject_reason`. Файлы хранить вне `static/`, отдавать только админам.
- Правило для аренды: публиковать место можно при `pending` или `verified` (иначе 403 «Подтвердите, что вы владелец места»). У объявления при `pending` фронтенд показывает «Проверка документов».

## Аренда (флаг `listings`)
**GET `/api/listings/`**: все объявления, у своих `"mine": true`.
```json
{"id": "501", "title": "Крытое место", "zone": "z12", "owner": "Алексей", "rating": "4,9", "reviews": 12,
 "hour_price": 3, "day_price": 15, "month_price": 180, "free": false, "when_text": "сб–вс, весь день",
 "avail": ["weekend", "tomorrow"], "walk": 3, "covered": true, "ev": false, "mine": false, "verified": true}
```
`avail`: `today`, `tomorrow`, `weekend`. Цены в белорусских рублях (BYN, на экране «руб.» или «Br»), копейки через точку. `null`, если формат не сдаётся. Номер места (`spot`) и улицу (`street`) отдаём всегда: гость видит их в объявлении, при бронировании и после подтверждения.

**POST `/api/listings/`**:
```json
{"zone": "z12", "date_from": "2026-11-01", "date_to": "2026-11-03", "all_day": true, "time_from": null, "time_to": null,
 "free": false, "hour_price": 3.5, "day_price": null, "month_price": null, "ev": false, "place_no": "128", "when_text": "1–3 нояб., весь день"}
```
Ответ 201 с объявлением. Нужны вход, паспортные данные и статус владельца (см. выше), иначе 401 или 403.

## Брони (флаг `bookings`)
**GET `/api/bookings/`**: `{"mine": [...], "incoming": [...]}`. `mine` это брони пользователя как гостя, `incoming` запросы к его местам.
```json
{"id": "9", "listing": "501", "fmt": "hour", "qty": 2, "qty_text": "2 ч", "when_text": "23 окт., с 19:00", "total": 7,
 "status": "request", "created_at": "23 окт., 13:30", "accepted_at": ""}
```
`status`: `request`, `confirmed`, `declined`. `fmt`: `free`, `hour`, `day`, `month`.

**POST `/api/bookings/`** `{"listing": "501", "fmt": "hour", "qty": 2, "date": "2026-10-23", "time": "19:00", "accepted_terms": true}`: ответ 201. Свое место бронировать нельзя (400). Итог считает сервер.

**POST `/api/bookings/<id>/answer/`** `{"accept": true}`: только владелец. Ответ: бронь. При подтверждении фиксируется время принятия договора обеими сторонами.

Позже (не обязательно сейчас): **GET `/api/bookings/<id>/contract/`** отдаёт текст договора, собранный на сервере; сейчас шаблон договора собирается на фронтенде.
