# Регистрация и вход: памятка для Насти

Весь доступ в аккаунт (регистрация, вход, выход, паспорт) лежит в одном файле: `static/js/auth/auth.js`. Остальной фронтенд его только вызывает, поэтому подключать базу данных можно, не трогая другие файлы. Точные поля запросов и ответов собраны в `docs/API.md`, раздел «Аккаунт»; здесь коротко, что делать и в каком порядке.

## Что в файле
| Часть | Что внутри | Когда менять |
|---|---|---|
| 1. Формы | HTML полей: фамилия, имя, отчество, телефон, почта, пароль; вход; паспорт | нужно другое поле |
| 2. Проверки | `checkSignup`, `checkPassport`: что считается правильным | другие правила |
| 3. Действия | кнопки «Создать аккаунт», «Войти», «Выйти», «Сохранить» | редко |
| 4. Сервер | запросы к Django, включаются флагом `auth` | подключаем базу |

Пока флаг выключен, аккаунт живёт только в памяти страницы (так сейчас), поэтому всё уже можно смотреть и нажимать.

## Что сделать на сервере (по порядку)
1. **Страница с cookie.** Главная страница приложения должна отдаваться через `@ensure_csrf_cookie`, иначе в запросах не будет `csrftoken` (пример: `backend-draft/main/api_zones.py`, функция `index`).
2. **Пользователь.** Расширить пользователя Django полями: фамилия, имя, отчество, телефон, а также идентификационный номер и номер паспорта (хранить зашифрованно). Почта используется как логин и должна быть уникальной.
3. **Пять адресов**, все возвращают JSON:

| Запрос | Что делает | Ответ |
|---|---|---|
| `POST /api/auth/register/` | создаёт пользователя и сразу открывает сессию | 201, пользователь |
| `POST /api/auth/login/` | вход по `email` и `password` | 200, пользователь; неверно: 401 |
| `POST /api/auth/logout/` | закрывает сессию | 204 |
| `GET /api/me/` | кто сейчас вошёл (страница спрашивает при открытии) | пользователь или 401 |
| `PUT /api/me/passport/` | сохраняет `pid` и `passport` | `{passport_set, pid_masked, passport_masked}` |

Тело регистрации: `surname, name, patronymic, phone, email, password`. Тело входа: `email, password`. Тело паспорта: `pid, passport`.

4. **Формат пользователя** (ответ регистрации, входа и `/api/me/`):
```json
{"id": 101, "surname": "Иванова", "name": "Анна", "patronymic": "", "phone": "+375291112233", "email": "a@mail.by",
 "passport_set": false, "pid_masked": null, "passport_masked": null, "owner": null}
```
Поле `owner` пока можно отдавать `null`: им занимается отдельный раздел (`docs/API.md`, «Владелец места»). Полный ИН и паспорт наружу не отдавать никогда, только маски.
5. **Ошибки** в виде `{"error": "Текст для человека"}` и нужным кодом. Текст показывается пользователю как есть, поэтому по-русски и без технических слов. Нужные случаи: почта уже занята (409, «Такая почта уже зарегистрирована»), неверный пароль или почта (401), пароль короче 6 знаков (400).
6. **Те же проверки, что на фронтенде.** Фронтенд проверяет форму для удобства, но сервер не должен ему верить: те же правила повторить в Django (пароль от 6 знаков, почта, ИН из 14 символов `\d{7}[A-Z]\d{3}[A-Z]{2}\d`, паспорт из двух букв и семи цифр).
7. **Включить.** В `templates/mesto_prototype.html` поменять `auth: false` на `auth: true`.

## Как проверить после подключения
1. Открыть сайт через `runserver`, вкладка «Аккаунт», «Новый аккаунт», заполнить и создать. В базе должен появиться пользователь.
2. Обновить страницу (Cmd+R). Человек остаётся вошедшим: страница спрашивает `/api/me/`.
3. Нажать «Выйти», затем «Уже есть аккаунт» и войти. Неверный пароль: показывается текст ошибки.
4. Зарегистрировать ту же почту второй раз. Должно быть сообщение «Такая почта уже зарегистрирована».
5. Добавить паспортные данные. В базе они лежат зашифрованно, а страница показывает только маску.

## Если нужно другое поле
Например, убрать отчество или добавить дату рождения. Меняются три места в `auth.js`: HTML в `signupCard()`, правило в `checkSignup()` и тело запроса в `ev('signup', …)`. Остальные файлы трогать не нужно.

## Как auth.js общается с остальным приложением
Через события страницы `mesto:…` и три готовых вызова: `AUTH.guestHtml()` и `AUTH.passportCard()` (формы для вкладки «Аккаунт») и `AUTH.needAccount()` (отправить человека на регистрацию, если он нажал «Забронировать» гостем). Событие `mesto:session` значит «понятно, кто сейчас на странице», по нему подгружаются объявления и брони. Событие `mesto:registered` значит «человек зарегистрировался как владелец места»: по нему `api/owner.js` отправляет его документы.
